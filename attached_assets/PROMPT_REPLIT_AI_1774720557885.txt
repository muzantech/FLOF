Tu es un développeur senior Node.js/Express. Tu vas construire FLYHOST, une plateforme d'hébergement gaming et applications. Implémente TOUT ce qui suit de façon complète, sans simplifier, sans mock, sans placeholder, sans TODO, sans "à compléter". Chaque fonction doit être entièrement fonctionnelle.

## STACK TECHNIQUE
- Backend : Node.js + Express
- Base de données : SQLite (via better-sqlite3)
- Panneau de contrôle serveurs : Pterodactyl Panel (API Application + Client)
- Paiement : MoneyFusion (FCFA/XOF)
- Proxy : http-proxy (Node.js natif)
- DNS : Cloudflare API
- Reverse proxy externe : Nginx (wildcard SSL *.flihost.site)
- Compression : AdmZip + archiver
- Git clone : child_process.exec (git CLI)
- PDF : pdfkit
- Email : nodemailer
- Rate limiting : express-rate-limit
- Authentification : JWT (jsonwebtoken) + bcrypt
- Upload fichiers : multer

## 3. SYSTÈME DE SOUS-DOMAINES & PROXY

### 3a. Middleware proxy — PREMIER middleware Express déclaré
- Extraire le hostname de req.headers.host
- Si sous-domaine de flihost.site : chercher en DB servers WHERE custom_subdomain = sous-domaine OU server_identifier = sous-domaine -> si trouvé : discoverContainerIp(server.alloc_port) puis proxy vers ip:port
- Si domaine custom : chercher en DB servers WHERE custom_domain = hostname -> proxy identique
- Cache JS Map avec TTL 60 secondes par hostname
- Si erreur proxy -> invalider le cache et réessayer une fois

### 3b. discoverContainerIp(port)
- Scanner le subnet Docker 172.18.0.1 -> 172.18.0.254
- Pour chaque IP, tenter une connexion TCP au port donné
- Retourner la première IP qui répond
- Mettre en cache containerIpCache[port] = ip

### 3c. Routes API sous-domaines
PUT /api/servers/:id/subdomain — Valider regex ^[a-z0-9-]{3,32}$, vérifier unicité, UPDATE servers SET custom_subdomain, invalider cache
PUT /api/servers/:id/custom-domain — Valider regex ^([a-z0-9-]+\.)+[a-z]{2,}$, UPDATE servers SET custom_domain, invalider cache

### 3d. ensureWildcardDNS()
- GET Cloudflare DNS records pour *.flihost.site
- Si absent -> POST pour créer record A *.flihost.site -> SERVER_IP (proxied: true)
- Appeler au démarrage du serveur

### 3e. syncAllocPortsFromPterodactyl()
- Toutes les 15 minutes
- Pour chaque serveur actif en DB : GET /api/application/servers/{ptero_id}
- Mettre à jour alloc_port si changé + invalider cache

## 4. DÉPLOIEMENT ZIP

POST /api/deploy/zip (multer upload):
1. Valider présence ZIP et server_id
2. Scanner entrées ZIP pour détecter la techno via TECH_ENVIRONMENTS
3. INSERT deployments (status: 'building', deploy_type: 'zip')
4. Lancer deployFromZip() dans un timeout de 10 minutes
5. Répondre immédiatement avec { deployment_id }

deployFromZip(deploymentId, zipPath, serverId, envVars):
1. saveSnapshot() -> copier le ZIP actuel dans uploads/snapshots/ (JAMAIS /tmp/)
2. Extraire dans /tmp/flyhost-deploy-{deploymentId}/
3. Flatten : si un seul dossier racine ET qu'il ne s'appelle pas 'src','lib','app' -> déplacer contenu à la racine
4. Supprimer node_modules/ et package-lock.json
5. Créer .env à partir de envVars
6. Vérifier taille totale < 500 MB
7. buildZipFromDir() -> créer ZIP propre
8. uploadZipToPterodactyl(serverIdentifier, zipBuffer)
9. autoSwitchEnvironment() -> changer egg Pterodactyl; si échec -> status='failed' et ARRÊTER
10. Poll /resources Pterodactyl toutes les 5s pendant max 3 minutes -> si 'running' : status='deployed'; si timeout : status='failed'
11. Nettoyer /tmp/flyhost-deploy-{deploymentId}/ dans un bloc finally
12. logDeployment() à chaque étape -> UPDATE build_log + global.broadcastLog() via SSE

uploadZipToPterodactyl(identifier, zipBuffer):
1. GET /api/client/servers/{id}/files/upload -> URL signée
2. POST ZIP vers URL signée via form-data
3. POST /api/client/servers/{id}/files/decompress { root: '/', file: 'upload.zip' }
4. DELETE /api/client/servers/{id}/files/delete { files: ['upload.zip'] }

## 5. DÉPLOIEMENT GITHUB

POST /api/deploy/github — Body: { server_id, repo_url, branch, env_vars, auto_deploy }:
1. Tenter GET flyhost.json depuis racine repo via GitHub API
2. Si absent -> detectTechnologyFromFiles() via GitHub Trees API
3. INSERT deployments (status: 'building', deploy_type: 'github', git_branch)
4. Lancer deployFromGitHub() en arrière-plan
5. Répondre immédiatement avec { deployment_id }

deployFromGitHub(deploymentId, repoUrl, branch, serverId, envVars):
1. saveSnapshot() -> uploads/snapshots/
2. git clone --depth 1 --branch {branch} {url} /tmp/flyhost-deploy-{id}/ — injecter token GitHub si disponible
3. UPDATE deployments SET git_commit = (git rev-parse HEAD)
4. Créer .env
5. Vérifier taille
6. buildZipFromDir() -> uploadZipToPterodactyl()
7. autoSwitchEnvironment() — si échec -> status='failed' et ARRÊTER
8. Poll status Pterodactyl jusqu'à 'running' ou timeout 3 min
9. Nettoyer /tmp/ dans finally

POST /api/webhook/github/:serverId:
- Secret HMAC unique par serveur (stocké en DB), vérifier X-Hub-Signature-256
- Si event='push' et branche = git_branch du serveur -> relancer deployFromGitHub()

GET /api/deploy/detect-tech — Body: { repo_url } ou { file_list }:
- Si repo_url : fetch GitHub Trees API
- detectTechnologyFromFiles(files) : comparer avec TECH_ENVIRONMENTS[].detect
- Retourner { tech, egg_id, confidence }

## 6. SUIVI DÉPLOIEMENTS SSE

GET /api/servers/:id/logs/sse:
- Auth via query param token=JWT
- Headers : Content-Type: text/event-stream, Cache-Control: no-cache
- Stocker res dans Map sseLogsClients[serverId]
- Envoyer immédiatement les 200 dernières lignes du build_log
- Heartbeat toutes 2s : data: {"type":"hb"}\n\n
- On close : supprimer de la Map

global.broadcastLog(serverId, message) -> event: log, data: { message, timestamp }
global.broadcastDeployStatus(serverId, status, message) -> event: status, data: { status, message }
global.broadcastDeployFailed(serverId, buildLog) -> analyzeDeployError(buildLog) puis event: failed, data: { suggestions[] }

analyzeDeployError(log) — retourner des suggestions précises pour :
- MODULE_NOT_FOUND -> "Vérifiez package.json et les dépendances"
- EADDRINUSE -> "Le port est déjà utilisé, redémarrez le serveur"
- ModuleNotFoundError -> "Ajoutez le module manquant à requirements.txt"
- Error: Cannot find module -> "Vérifiez le point d'entrée dans flyhost.json"
- permission denied -> "Problème de permissions sur le fichier d'entrée"

- Sauvegarder dans uploads/snapshots/{serverId}/{deploymentId}-{timestamp}.zip

POST /api/deploy/:deploymentId/rollback/:snapshotId:
1. SELECT deployment_snapshots WHERE id = snapshotId
2. Vérifier que snapshot_path existe sur le disque
3. uploadZipToPterodactyl() avec le fichier snapshot
4. UPDATE deployments SET status='deployed'

## 15. SÉCURITÉ & ANTI-ABUS

authLimiter : 5 requêtes / 15 minutes par IP sur routes /api/auth/*
apiLimiter  : 100 requêtes / minute par IP sur toutes routes /api/*

requireEmailVerification : middleware appliqué sur toutes routes de déploiement et paiement

Sanitization flyhost.json — avant toute injection dans Pterodactyl :
- start_cmd : regex whitelist ^[a-zA-Z0-9 ./\-_${}]+$ — rejeter si non conforme
- node_version : liste blanche ['18','20','22'] uniquement
- Ne JAMAIS interpoler directement dans exec() sans validation

Vérification coins atomique (transaction SQLite) avant toute opération monétaire :
- BEGIN TRANSACTION -> SELECT coins FROM users WHERE id = ? -> if coins < price -> ROLLBACK + erreur -> sinon UPDATE + COMMIT

Chaque action sensible -> INSERT audit_logs (user_id, action, ip_address, details, created_at)
